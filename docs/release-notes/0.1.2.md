Sonora Sound Recorder **0.1.2** is a bug-fix and security release. It fixes problems when stopping and saving recordings, with long file names and with updates, and moves to an Electron release with the latest Chromium and V8 security fixes.

## Fixed

- **Stopping a recording.** Stopping could collide with Sonora's periodic write to disk. You could then see a "recording failed" message for a recording that was saved correctly, or the stopped recording was offered as a crashed one. Stopping now waits for the write to finish.
- **Disk full while stopping.** When the last write of a recording failed, for example because the disk was full, the recording stayed open until Sonora restarted. It is now closed and offered as a recovered recording right away.
- **Failed saves and exports.** If FFmpeg failed while saving or exporting, a hidden `.sonora-partial` file could stay in the recordings or export folder. It is now removed.
- **Long names in other scripts.** A long name in Cyrillic, Chinese or with emoji could exceed the 255-byte file name limit of Linux and macOS, and saving failed. Names are now shortened so that they always fit. On Windows, a shortened name no longer ends with a dot or a space.
- **Checking for updates after a download.** *Check now* forgot an update that was already downloaded, or an install that was waiting for recordings to finish. Both are now kept.
- **Update download errors.** If an update could not be written to disk, the download hung forever. It now shows an error.
- **Notifications.** A new notification restarted the timers of the ones already shown, so older notifications could stay on screen much longer than intended. Each notification now closes after its own time.
- **Mini panel on Linux.** The mini panel now remembers its position on Linux too.
- **Folders and tags.** Renaming a folder or tag to the name of another one is refused, as creating one already was.
- **Robustness.** A malformed internal page address no longer causes an error in the main process, and a failed background settings write no longer leaves an unhandled error in the log.

## Security

- **Electron 44.9.3** (from 44.7.2): Node.js 24.22.0, Chromium 152.0.7977.167, backported security fixes from Chromium, V8, ANGLE, PDFium and Skia, and the mitigation for the compromised eMudhra intermediate certificates.
- **Node.js on the build machines.** Node.js versions before the [October 21, 2026 security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) are affected by a Brotli decoder remote code execution (CVE-2026-111497), TLS hostname verification bypasses (CVE-2026-105483, CVE-2026-106069), a DNS name truncation issue (CVE-2026-105482) and six further issues. Node.js 18 and 20 are end of life and receive no fixes. All CI and release jobs now run on Node.js **24.22.1**, the fixed 24.x version, instead of the version that happened to be installed on the runner. `package.json` requires 22.23.4, 24.22.1 or 26.12.1 or newer.
- **Sonora itself** does not use Node's `http`, `tls`, `dns` or `zlib` modules: update checks and downloads go through Electron's `net` module (Chromium's network stack). The Node.js 24.22.1 fixes will reach the app with the next Electron 44 release that includes them.
- **Test tooling:** Vitest 4.1.12 (from 3.2.7) removes the critical Tinypool prototype-pollution advisories (GHSA-5gmw-xhrv-c9v3, GHSA-85c8-ppgw-ccpr) and the `@vitest/mocker` advisories. This only affects development; none of it is part of the app.

## Verified on CI

- Type checks for the main process and the interface, and all unit and integration tests, including new tests for stopping during a disk write, closing a recording whose last write fails, cleaning up after a failed save, long non-Latin file names, keeping a downloaded update, update download errors and duplicate folder and tag names.
- Real encodes of all five formats with the bundled FFmpeg, and packaging plus package verification (contents, architectures, a transcription smoke test) on Windows x64, macOS arm64, macOS x64 and Linux x64.

## Known limitations

These are unchanged from 0.1.1:

- The packages are not code-signed or notarized.
- System audio on macOS needs version 13 or newer and the Screen Recording permission.
- Microphone and system audio capture, global shortcuts and the mini panel's keyboard handling cannot be exercised on CI runners. The manual checks are listed in `docs/TESTING.md`.
