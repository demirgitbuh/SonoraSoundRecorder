## Fixed

- **Shortcuts in the mini panel.** While the mini panel had focus — for example right after clicking one of its buttons — K, Space and L did nothing: global shortcuts are released whenever a Sonora window is focused, but the mini panel had no key handling of its own. The panel now handles the recording shortcuts itself, for both *Everywhere* and *Only in Sonora*, and acts on the selected session like everywhere else. Space no longer re-presses a button that was clicked with the mouse, and the button tooltips show the current keys.
- **Recorder window crash during a recording.** If the recorder window crashed while recording, the recording stayed open in the background and was not offered after the window reloaded. Sonora now closes such recordings safely first, and the reloaded window offers them as recovered recordings.
- **No default application menu.** Sonora no longer installs Electron's default menu, so its reload and developer-tools shortcuts cannot interrupt a recording. On macOS the application, edit and window menus remain. The developer tools are available in developer mode.

## New: developer mode

Turn it on in **Settings → Advanced → Developer mode**. A **Developer** page appears in the sidebar. Turning developer mode off restores the standard behavior at once and keeps your values for later. Full details: [docs/DEVELOPER.md](https://github.com/demirgitbuh/SonoraSoundRecorder/blob/main/docs/DEVELOPER.md).

- **Overview:** versions of Sonora, Electron, Chromium, Node.js and V8, OS and hardware, live CPU and memory of every Sonora process, the executables in use with their versions, all data folders, applied Chromium switches and graphics status, and *Copy diagnostics* as JSON.
- **Live log:** streaming log with level, source and text filters, pause and copy; lowest written level; optional IPC call tracing and FFmpeg/whisper command-line logging.
- **Audio engine:** latency mode, worklet chunk size, meter rate, clip threshold, send interval, disk sync interval and no-audio timeout; a live view of every session's audio graph; simulated microphone or system-audio disconnects to test the reconnect path.
- **FFmpeg & whisper:** use your own FFmpeg, FFprobe or whisper-cli build (checked before it is accepted); whisper.cpp beam size, best-of, temperature, segment length, context, initial prompt, translation, word splitting, fallback, non-speech suppression, GPU and flash attention, with a preview of the resulting command; keep transcription work files; an FFprobe inspector.
- **System:** hardware acceleration, Sonora's platform switches and extra Chromium `--enable-features` / `--disable-features`, applied at the next start; a performance overlay; internal IDs in the archive; a DevTools shortcut; pre-release updates; DevTools for the main window and the mini panel.
- **Tools:** a key tester with the registration state of every shortcut, test recordings generated with FFmpeg, sizes of Sonora's data files with a read-only viewer, clearing temporary files, running the first-start setup again, a deliberate recorder crash to test recovery, and restart.

Safety rules: every developer channel is refused while developer mode is off; executable paths and Chromium switches are never taken from imported settings or profiles; Chromium switches are read defensively at start-up, so a broken value can never stop Sonora from starting.

## Known limitations

These are unchanged from 0.1:

- The packages are not code-signed or notarized.
- System audio on macOS needs version 13 or newer and the Screen Recording permission.
- Microphone and system audio capture, global shortcuts and the mini panel's keyboard handling cannot be exercised on CI runners. The manual checks are listed in `docs/TESTING.md`.
