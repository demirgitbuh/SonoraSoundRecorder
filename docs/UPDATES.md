# Updates and data protection

## How updates work

Sonora checks its own GitHub Releases (`demirgitbuh/SonoraSoundRecorder`) at startup, if the option is enabled, or when you click **Check now** in *Settings → Updates*. When a newer version exists, Sonora shows:

- the installed and the new version number,
- the release notes,
- three choices: **Download**, **Download and update** and **Later**.

Nothing is downloaded or installed without your choice. Download progress, errors and *Try again* are shown.

| Package | What "update" does |
| --- | --- |
| Windows installer (NSIS) | downloads the new installer (verified with SHA-512 from `latest.yml`) and upgrades the existing installation after confirmation |
| Linux AppImage | replaces the AppImage after confirmation |
| Windows portable | cannot replace itself; downloads the new portable file and shows it in its folder |
| macOS DMG | downloads the disk image (verified with SHA-256 when GitHub provides a digest) and opens it; drag the app to Applications |
| Linux DEB | downloads the package and opens it with your system's package installer |

**Recording in progress?** Sonora never restarts automatically while a session is recording, finishing or saving. The installation waits until everything is idle.

## What is kept

All of this lives in the operating system's user-data folder, **separate from the installation folder**, and is never touched by installing, updating or uninstalling. The Windows installer is configured with `deleteAppDataOnUninstall: false`.

- recordings (in your own recordings folder)
- settings, language, theme and shortcuts
- archive metadata, edit metadata, markers and notes
- folders, tags and favorites
- the trash
- transcripts
- the local model path (the model file itself stays wherever you put it)
- unsaved and recoverable recordings

Every data file carries a schema version. Newer releases migrate older files. A file written by a newer version is kept as a copy before an older version reads it.

These rules are covered by automated tests: see `tests/update-data.test.ts` and `tests/settings.test.ts`.

## Release metadata

Each release contains the packages plus `latest.yml` (Windows installer) and `latest-linux.yml` (AppImage). These are generated by electron-builder in the same run that produces the packages, so their file names and checksums always match the uploaded assets.
